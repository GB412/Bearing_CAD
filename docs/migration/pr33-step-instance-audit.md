# PR33 — STEP 逐实例质量门禁与报告一致性

目标：消除靠体积猜测“角接触窗孔保持架”的错误容差授权。保持现有几何模型、原始 API 和 STP 格式不变。

**源零件身份**：从 `AssemblyModel.components`、`instances` 取 `component_id`、`instance_id`，用同一 `cq.Location` 把原型 B-Rep 变换至实际装配坐标。对从 STEP 回读的匿名实体，只在各**源零件专属的体积、质心、包围盒误差**都不超限时建立候选匹配，并使用一对一增广路径匹配（不依赖 STEP 顺序）。这是实例证据的几何匹配，不声称 STEP 导入器保留了组件名称。若出现不可匹配实体，**拒绝生成**。

**容差**：圈体、滚动体、独立挡圈、铆钉和其他普通零件保留体积 5e-4、质心 0.001 mm；仅 `rolling.angular_contact_ball` 中 `component_id=cage` 且 `role=cage` 的实例保留原先测得的 1.2e-3 与 0.005 mm。装配总包围盒保留 0.001 mm 门禁，局部 bbox 单独受约束。容差是 OCCT STEP 格式交换约束，**不是制造公差**，不能作为其他零件的自动兜底。

**报告**：`geometry_quality.json` 的 `step_roundtrip.per_instance_metrics` 逐实例输出源零件 ID、STEP 实体索引、实际体积误差/阈值、实际质心误差/阈值、bbox 误差/阈值、是否特殊容差与是否通过。顶层 `allowed_*` 变成实际使用上限最大值，增加 `default_*` 说明，并保留历史的 `worst_*`、`radial_window_cage_*` 兼容读取。***判断是否合格必须逐实例比较，不应把全局最大误差直接与某个通用阈值比较。***

**防回归**：有两个体积相等的已知不同组件（内圈与保持架），STEP 故意改变顺序时应仍逐实例配对；只改变内圈体积约 0.08%（介于通用 0.05% 与保持架 0.12% 之间），必须失败。三类轴承及多保持架的原本 STEP 测试、七组 RoBAS 基准和真实浏览器联调保持通过。

缓存生成器从 0.9.5 更新到 0.9.6，防止旧质量报告作为新门禁结果重用。本阶段不修改制造级精度结论，不进行复杂通用 B-Rep 语义识别。
