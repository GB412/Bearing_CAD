# PR-OPT-01：RoBAS DGB 多目标优化候选、比较和人工确认

## 任务边界

当前 Bearing_CAD 的三维与二维请求采用同一份完整几何参数：DGB 需要 d、D、B、Dw、Dpw、Z、沟道曲率、挡边和可选保持架。但初始优化不应要求用户先确定全部内部几何。

此 PR 仅迁移 DGBOptimizer 首个真实候选搜索：
- 输入：轴承类型、原版型号 60/62/63 系列、d/D/B、精度等级、径向游隙组、Cr 与 Kr 权重（默认 0.8/0.2，之和必须为 1）、是否保留简化环缘保持架。
- 搜索：原版 BallDB.csv 球径附近五点、球数五点、最多四个节圆点；原版 Kwmin/Kwmax/Phimax/Kd 规则；载荷系数精确来自球轴承零件相关系数.csv；原版 Cr、Cor 和经验径向刚度公式。
- 结果：按评分给出最多五组 Dw/Z/Dpw 和完整几何参数，但不直接改变当前 CAD 表单。
- 用户明确点击“确认并应用此设计”，才更新现有 CAD 输入。之后分别使用现有 3D OCCT 及 2D RoBAS CADImport 生成入口；无需改动已完成的 DWG/SQLite/CSV。
- 需要额外校验：基础几何包络、互不穿透、CAD 请求合同、原版 BearingType.db 已知型号与 d/D/B 的一致性。仍需真实 3D B-Rep、Windows DXF 和 AutoCAD 验收。

## 与原版行为的区别

DGBOptimizer 原版算法的 getEvaluationCoefficientsIndex 最后返回 secondMaxIndex，可能选中第二高分。此 PR 保留原版搜索与评分思想，但正确按降序排列，不直接写入最优参数；由用户挑选。BaseOptimizer 对单一指标全相等会除以零，此 PR 统一按零区分度处理，不假造优势。

精度等级、游隙组仅作为已明确的输入/来源追溯。原版这些目标公式没有直接依据它们改变 Cr/Kr 评分；不能因此声称已按照实际工作游隙或拟静力工况优化。冲压保持架在变更 Dw/Z/Dpw 后需要重新设计，因此本 PR 禁止把已有冲压双半笼照搬到优化候选。

## UI 操作顺序

1. 在现有 CAD 工作台选 DGB，填写初始 d/D/B。
2. 点击“设置型号/精度/游隙组”跳到二维设置，填写如 6008、P5、C0，再返回三维。
3. 设置 Cr 与径向刚度权重，点击“生成优化候选”。
4. 比较多组 Cr（kN）、经验径向刚度、钢球尺寸/数量、评分；此时 CAD 表单不变。
5. 点击某组“确认并应用此设计”，当前完整几何输入才改变，旧的 CAD 预览失效。
6. 再点击三维模型生成或二维图纸生成；两项读取相同参数。
7. 修改初始尺寸、型号或权重后，未确认的候选必须重新计算。

## 目前缺少哪些输入

| 功能 | 初始必需信息 | 迁移状态 |
|---|---|---|
| DGB 多目标 | d/D/B、型号、精度/游隙组、Cr/Kr 权重 | 本 PR |
| ACB 多目标 | d/D/B、接触角、预载荷、保持架材料、旋滚比/Ka/Cr 权重 | 尚需后续 PR，现有 CAD 请求缺预载荷 |
| CRB 多目标 | d/D/B、挡边构型、滚子约束、Cr/Kr 权重 | 尚需后续 PR；源 Kr 返回零，不能直接当有效双目标 |
| 复杂拟静力分析 | 已确认几何及 Fx/Fy/Fz、转速、温度、材料、润滑、求解控制 | 尚需后续 PR 接入 RoBAS_v2.exe；目前没有完整分析工况表单 |

这次只关注 DGB 候选与人选后的二维/三维共用参数闭环，不在本 PR 开始 EXE 求解器或另两个优化器。所有结果属于非制造批准候选。

## 验证

- Python：源 CSV/型号/范围、候选完整性、权重边界、未确认只读、错误输入及同源 API。
- Playwright：未确认不修改 CAD；确认后 2D/3D 请求使用相同的 Dw/Z/Dpw；修改输入后候选失效。
- Linux CI 不代表本机 Windows CADImport、AutoCAD 字体/图框或制造批准。
