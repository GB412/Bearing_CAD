# PR35 · 前端仅保留轻量几何提示，Python/OCCT 最终判断

`rolling_manifest.js` 的 `geometryIssues()` 曾复制了钢球/滚子间距三角公式、沟道圆环切削几何、径向净距/轴向净距与保持架窗口关系。随着 Python 构造器迭代，前端可能错误拒绝本可建模的输入。

本 PR 删除重复的高级几何公式，**只保留**内外径、节圆、肩部/挡边径向顺序，以及保持架宽度/内外径大小等简单、稳定的不等式。原有数字格式、资源上限、接触角范围、数值非有限/负值检查不变。

- 前端输入更改时仍立即给出中文提示；例如只改角接触内径 40→50，依然标出冲突的内圈左右肩。
- 对钢球碰撞、径向沟道切削、轴向挡边净距、球兜窗孔等高级规则，**后端 Python 是最终权威**。点击生成将真实请求交给 API，后端 422 仍按 field_path/highlight 呈现，不允许产生无效 STEP。
- 新增 Node 测试，确保被移走的复杂规则由后端最终决定；保留既有 3 类轴承与保持架默认参数验收、浏览器实际 API、中文错误提示。
- 不新增 JSON 规则 DSL、额外 Python service、规则注册器；保留现有 geometry builder 的物理语义边界。
- 已知要求：后端字段级错误尽量使用明确 field_path。对于较复杂的 API 校验，仍可能给出 `/parameters` 总体路径，未来只有明确的用户案例才逐步细化。

这属于代码维护性修复，不新增轴承自动设计能力，也不修改 CAD 实体、STEP 文件、缓存哈希与 RoBAS 对比结论。
